## Two holes in the permission model

- **M-10 (corrected).** The original filing said the denies never match a sandbox path. Wrong.
  Overwriting an *existing* guarded file in a sandbox is refused; creating a *new* file in a guarded
  directory succeeds. The new-file half is the dangerous one — a brand-new workflow runs arbitrary
  code with the repository's secrets.
- **M-12 (new).** The denies are per-tool. `Edit`, `Write` and `cp` all refused the guarded workflow
