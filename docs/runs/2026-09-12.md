### #47 — CI was red because the test was wrong, not the gate

survive. That control **fired on CI while passing locally, and it was right to.** `pathWithout`
removed every `PATH` directory holding a file of that name, and `corepack enable` installs pnpm into
node's *own* bin directory — so on the runner, removing `node` removed `pnpm` with it.

Reproduced locally before changing anything, by symlinking both runners into one directory:

```
FAIL tests/gate-check.test.ts:390
AssertionError: node: expected '' not to be ''
```

Replaced `PATH` subtraction with `pathWithRunners`, which builds the `PATH` from a directory the test
owns and re-supplies any utility the strip took. Added a control that every utility `gate-check.sh`
needs still resolves — otherwise an UNPROVEN verdict could mean a missing `grep` rather than a
missing runner.

Mutation control: blinding the pnpm probe in `runner_problem()` still fails the test under both
`PATH` layouts. `scripts/gate-check.sh` unchanged.

### #33's landing condition 2 cannot be satisfied as written

The landing agent may merge only when "**`fresh-reviewer` has approved** this change set". Under the
current setup that state is unreachable:

- every PR in this repo is authored by `swaraadam`
- agents review under that same account
- GitHub refuses self-approval, so the review is recorded `COMMENTED`

Evidence: the only two reviews ever recorded in this repo are `#29 swaraadam:COMMENTED` and
`#33 swaraadam:COMMENTED` — and #38's run report already documents one of those as an `approve`
verdict that GitHub would not record as an approval.

So the gate as written either never merges, or is satisfied by reading a `COMMENTED` review as an
approval — which is the same "asserting a verification stronger than the one run" defect that
stopped the 2026-09-10 run. **This needs an owner decision before #33 lands.** A separate reviewer
account is not available: §8 forbids third-party account creation.
