# Try this — 2026-09-14

The gateway serves the office state from durable rows.

Everything below was run end to end on 2026-09-14 and the output is transcribed, not predicted. One
edit: the absolute path of the checkout is written `<repo>`, because it is this machine's and not
yours. Nothing else is reformatted — the JSON is exactly what `python3 -m json.tool` printed, four
space indent and all, and the `$ ` lines pnpm echoes are left in.

Three commands from a clean clone.

## 0. Install

```bash
pnpm install
```

Ordinary package manager output, not reproduced here: it is the only step whose output depends on
your machine rather than on this repository.

## 2. Start the gateway

```bash
pnpm dev
```

```
$ ./scripts/dev.sh
$ node -e "import('./dist/src/index.js').then(m=>m.start()).catch(e=>{console.error(e&&e.name==='GatewayStartupRefusal'?e.message:e);process.exitCode=1})"
gateway listening on http://127.0.0.1:4319  database: <repo>/state/dev/control-plane.sqlite
```

`pnpm dev` does one thing the gateway is not allowed to do for itself: decide **which database**.
`apps/gateway` does not know the repository root and must not spell product filenames while naming
clearance is an open Phase -1 gate (CLAUDE.md §1), so it refuses to start unless something passes it
an absolute `SEED_DB_PATH`. `scripts/dev.sh` reads that path from `DEV_DB_PATH` — the export of the
same `scripts/seed.ts` that step 1 ran, which takes the filename from `config/naming.ts`. One
definition, two readers.

## What to actually look at

This is the part worth thirty seconds, because it is the whole thesis.

**`dev-task-03` says `"basis_staleness": "unknown"`, and it is not dispatched.** A re-probe did not
complete, so the system does not know whether the plan is still valid — and it says so, in the
payload, with the reason attached. It did not round the unknown down to `stale` or up to `fresh`.
Invariant 4: unknown fails closed and refuses dispatch.

**Its `basis_ref` is still `basis-0003`.** A basis *was* captured. Nulling it to express doubt would
be a different lie — "no basis was ever captured". What is indeterminate is its *staleness*, and
that is the field carrying the doubt.

**`dev-task-01` says `"basis_staleness": null`, not `"fresh"`.** Nothing in the log ever assessed
that task's staleness, so the gateway declines to claim one. `null` means "no assessment is on the
record". `fresh` is never a default — it has to be earned by an event that says so. This is the
distinction the whole endpoint exists to preserve, and it is why the field is nullable rather than
defaulted.

**`dev-task-04` holds `bundle-build` with disposition `held-by-frozen-task`, and `dev-repair-04` has
`resolution: null`.** Mutation is frozen and stays frozen. Only an owner writes that resolution;
nothing in this process can clear it.

## What it does when you skip step 1

The same discipline applies to startup. Run `pnpm dev` against a machine that has never been seeded
and nothing starts:

```
$ rm -rf state/dev
$ pnpm dev
$ ./scripts/dev.sh
pnpm dev did not start the gateway: there is no database yet.
  expected: <repo>/state/dev/control-plane.sqlite

Run `pnpm seed` first. It writes durable rows and events under state/dev/ for the office
to read. Starting against a missing file would create an empty database, and an empty
office is a claim durable truth never made.
[ELIFECYCLE] Command failed with exit code 1.
```

And the gateway itself, asked to start with nothing naming a database:

```
$ pnpm --filter @internal/gateway start
$ node -e "import('./dist/src/index.js').then(m=>m.start()).catch(e=>{console.error(e&&e.name==='GatewayStartupRefusal'?e.message:e);process.exitCode=1})"
refusing to start: no database was named.
  set SEED_DB_PATH to the absolute path of the control-plane database.
  `pnpm dev` does this for you from the one source (config/naming.ts via scripts/seed.ts);
  this process does not name database files and does not know the repository root.
[ELIFECYCLE] Command failed with exit code 1.
Error: ERR_PNPM_RECURSIVE_RUN_FIRST_FAIL

  × "pnpm recursive run" failed in /private/tmp/claude-501/-Volumes-ex2990-
  │ Projects-Personal-ruang/8307f003-4f33-46a0-a002-9e13801b70ba/scratchpad/
  │ p0-09-v2/apps/gateway

```

Neither one opens a file it guessed at. better-sqlite3 would happily *create* the database at a path
that does not exist, and the office rendered from it would show no projects, no tasks and no locks —
a confident, well-formed claim that durable truth never made. Refusing is invariants 1 and 4 applied
to the first thing that happens.

## What this is not, yet

- **There is no UI.** `/api/office/state` is the surface. The office renderer is Phase 6.
- **`seq` is a resume point, not decoration.** `GET /api/office/events?since=20` is a WebSocket that
  replays exactly the gap and tells you to re-snapshot rather than hand you a partial history. It is
  in this change set and tested, but the interesting demo needs a writer, which does not exist yet.
- **No endpoint accepts a command string.** Not an omission — it is the design. A browser reaching
  this process cannot ask it to run anything.

which is the working directory pnpm gives that script. The flow above is now covered by

database, so the next time the wiring breaks a test says so before a document does.
