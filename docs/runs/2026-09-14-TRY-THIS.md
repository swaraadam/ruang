The gateway serves the office state from durable rows.

Everything below was run end to end on 2026-09-14 and the output is transcribed, not predicted.
Three edits, all mechanical: the absolute path of the checkout is written `<repo>`, because it is
this machine's and not yours; a throwaway temporary directory is written `<tmp>` for the same
reason; and the places where pnpm wrapped that path across lines are elided in square brackets

## 2. Start the gateway

```bash
pnpm dev
```

```
$ ./scripts/dev.sh
$ node -e "import('./dist/src/index.js').then(m=>m.start()).catch(e=>{console.error(e&&e.name==='GatewayStartupRefusal'?e.message:e);process.exitCode=1})"
gateway listening on http://127.0.0.1:4319  database: <repo>/state/dev/control-plane.sqlite
```

`pnpm dev` does two things the gateway is not allowed to do for itself: decide **which database**,
and decide **which origin is canonical**. `apps/gateway` does not know the repository root and must
not spell product identifiers while naming clearance is an open Phase -1 gate (CLAUDE.md §1), so it
refuses to start unless something passes it an absolute `SEED_DB_PATH` and a `CANONICAL_ORIGIN`.
`scripts/dev.sh` reads the first from `DEV_DB_PATH` — the export of the same `scripts/seed.ts` that
step 1 ran — and the second from `config/naming.ts` directly. Both trace back to that one file; a
second spelling of either is the defect this arrangement exists to make impossible.

## 3b. Ask it from somewhere else, and it refuses

The port is bound to `127.0.0.1`, which keeps the network out. It does not keep the **browser** out:
a WebSocket handshake is exempt from the same-origin policy, so any page you visit could open the
event stream and read the whole durable log, and any hostname an attacker points at `127.0.0.1` could
reach the HTTP route with the browser's CORS backstop no longer in the way. Both halves are checked
now, on one hook, before routing.

```
$ curl -s -i -H 'Origin: https://evil.example' http://127.0.0.1:4319/api/office/state
HTTP/1.1 403 Forbidden
content-type: application/json; charset=utf-8
content-length: 90
Date: Mon, 14 Sep 2026 14:45:12 GMT
Connection: keep-alive
Keep-Alive: timeout=72

{"error":"forbidden_origin","detail":"Origin is not the canonical origin of this gateway"}

$ curl -s -o /dev/null -w '%{http_code}\n' -H 'Origin: null' http://127.0.0.1:4319/api/office/state
403

$ curl -s -H 'Host: office.evil.example' http://127.0.0.1:4319/api/office/state
{"error":"forbidden_origin","detail":"the Host header does not name this gateway"}
```

`Origin: null` is refused **by name**: it is the literal string a sandboxed iframe sends, and reading
it as "no Origin" is the usual way an allowlist becomes optional. The `Host` check is the half that
closes DNS rebinding — `office.evil.example` may resolve to `127.0.0.1`, but the browser still sends
the name it was given, and a gateway that answers to any name answers to that one.

A **missing** `Origin` is treated differently on the two doors, deliberately. The WebSocket upgrade
refuses it: RFC 6455 requires a browser to send `Origin` on a handshake, so its absence means "not a
browser", and the browser is the entire threat model for that stream. The HTTP route accepts it,
because browsers omit `Origin` on same-origin `GET` — requiring it there would refuse the office's own
fetch and `curl` above, while blocking nothing: a cross-origin browser *read* always carries `Origin`,
a cross-origin load that does not (an `<img>`, a `<script>`) cannot read what it triggers, and the one
real no-Origin read is DNS rebinding, which the `Host` check already refused. When the browser does
send `Sec-Fetch-Site`, only `same-origin` and `none` get through.

Nothing here is authentication. It is the one canonical origin, enforced. Authentication is Phase 3.

## What to actually look at

This is the part worth thirty seconds, because it is the whole thesis.

**`dev-task-03` says `"basis_staleness": "unknown"`, and it is not dispatched.** A re-probe did not
complete, so the system does not know whether the plan is still valid — and it says so, in the
payload, with the reason attached. It did not round the unknown down to `stale` or up to `fresh`.
Invariant 4: unknown fails closed and refuses dispatch.

**Its `basis_ref` is still `basis-0003`.** A basis *was* captured. Nulling it to express doubt would
be a different lie — "no basis was ever captured". What is indeterminate is its *staleness*, and
that is the field carrying the doubt.

**`dev-task-01` says `"basis_staleness": null`, not `"fresh"`.** Nothing in the log ever assessed
that task's staleness, so the gateway declines to claim one. `null` means "no assessment is on the
record". `fresh` is never a default — it has to be earned by an event that says so. This is the
distinction the whole endpoint exists to preserve, and it is why the field is nullable rather than
defaulted.

**`dev-task-04` holds `bundle-build` with disposition `held-by-frozen-task`, and `dev-repair-04` has
`resolution: null`.** Mutation is frozen and stays frozen. Only an owner writes that resolution;
nothing in this process can clear it.

## What it does when you skip step 1

The same discipline applies to startup. Run `pnpm dev` against a machine that has never been seeded
and nothing starts:

```
$ rm -rf state/dev
$ pnpm dev
$ ./scripts/dev.sh
pnpm dev did not start the gateway: there is no database yet.
  expected: <repo>/state/dev/control-plane.sqlite

Run `pnpm seed` first. It writes durable rows and events under state/dev/ for the office
to read. Starting against a missing file would create an empty database, and an empty
office is a claim durable truth never made.
[ELIFECYCLE] Command failed with exit code 1.
```

And pointed at a file that exists and is not this system's database — a stale path, a restored backup,
a symlink, an unrelated `.sqlite` — it refuses that too, **without writing anything into it**:

```
$ SEED_DB_PATH=<tmp>/notes.sqlite pnpm dev
$ ./scripts/dev.sh
$ node -e "import('./dist/src/index.js').then(m=>m.start()).catch(e=>{console.error(e&&e.name==='GatewayStartupRefusal'?e.message:e);process.exitCode=1})"
refusing to start: <tmp>/notes.sqlite is not this system's control-plane database.
  expected: schema version 1, 26 tables
  found:    schema version 0, 1 table (notes)
  Nothing was written to it: the check reads through a read-only handle precisely so that
  a file which turns out to belong to something else is left exactly as it was found.
  Serving it would answer with an office assembled from a database nobody here wrote.
[ELIFECYCLE] Command failed with exit code 1.
Error: ERR_PNPM_RECURSIVE_RUN_FIRST_FAIL
[pnpm's own tail, naming <repo>/apps/gateway, elided: it wraps the path across lines]
```

That last one is the interesting refusal, because the obvious version of this check is wrong. Asking
whether a file **exists** is not asking whether it is **ours**: `existsSync` follows symlinks, and
better-sqlite3 opens whatever it finds, at which point the migration writes twenty-six control-plane
tables into someone else's database and the office is served back from it with no projects and no
tasks. Identity is proved first, through a read-only handle — so a file that turns out to belong to
something else is byte-for-byte as it was found, including the `notes` table above and its
`user_version` of 0.

Neither one opens a file it guessed at. better-sqlite3 would happily *create* the database at a path
that does not exist, and the office rendered from it would show no projects, no tasks and no locks —
a confident, well-formed claim that durable truth never made. Refusing is invariants 1 and 4 applied
to the first thing that happens.

## What this is not, yet

- **There is no UI.** `/api/office/state` is the surface. The office renderer is Phase 6.
- **`seq` is a resume point, not decoration.** `GET /api/office/events?since=20` is a WebSocket that
  replays exactly the gap and tells you to re-snapshot rather than hand you a partial history. It is
  in this change set and tested, but the interesting demo needs a writer, which does not exist yet.
  It refuses a log with a hole in it from **every** resume point, not only from points before the
  hole — the same question, asked of the same log, that makes the snapshot route answer 409.
- **There is no authentication.** The origin check above says *which page* may talk to this gateway.
  It says nothing about *who*. Anything that can set its own headers — `curl`, another process on
  this machine — reaches it, and that is Phase 3's problem, named here rather than left implied.
- **No endpoint accepts a command string.** Not an omission — it is the design. A browser reaching
  this process cannot ask it to run anything.
