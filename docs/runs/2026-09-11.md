### P0-02 — what changed and why it is two change sets, not one

The 665-line `p0-02` branch is superseded, not amended. Its `events.ts` published all 53 durable
event types with a payload schema for each; Appendix A.1 specifies **names only**. Those 53 shapes
were invented, and a closed union is exactly the construct that would have made downstream issues
treat them as specified.

What lands instead is only what A.3 actually fixes:

- **`p0-02-1-envelope`** — `check.ts` (structural validators, no new runtime dependency),
  `envelope.ts` (`PROTOCOL_VERSION`, `Actor`, `EventEnvelope`, `ENVELOPE_FINGERPRINT`,
  `isEnvelopeOf`, `assertNever`). `isEnvelopeOf` takes the payload validator **from its caller**:
  this module never asserts what a payload contains, because nothing specifies that yet.
- **`p0-02-2-ephemeral`** — the six A.2 channels in a module that shares no type with the
  envelope, reachable only as the `@internal/protocol/ephemeral` subpath.

Acceptance status on #2 after both land:

| | criterion | status |
|---|---|---|
| 1 | exhaustive switch compiles with a never check | **OPEN** — `assertNever` ships; the closed union it guards needs the catalog |
| 2 | persistence signature cannot accept an ephemeral message | **MET** |
| 3 | seam audit clean on every exported name and field | **MET** |
| 4 | adding a type without bumping `PROTOCOL_VERSION` fails a test | **half** — the envelope half is pinned; the catalog half is OPEN |

1 and 4 stay open by design. They need the payload catalog, and the catalog needs schemas that do
not exist. **This wants a new backlog item** — "durable event catalog, once Appendix A.1 payloads
are specified" — dependent on #2 and on you or the blueprint supplying the shapes. I did not add
it: inventing the issue would be the same move as inventing the payloads.
