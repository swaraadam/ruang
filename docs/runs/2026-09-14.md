### #72 is the night's most important result

It was `MERGEABLE/CLEAN`, carried a valid SHA-bound pass marker, and **would have been landable**.
The security review found two criticals, both verified empirically against real tmux and real
symlinks rather than inferred from reading:

- **C1** `sessions.ts:96-105` spreads caller-supplied `spec.command` into the tmux argv with no
  validation and no `--`. tmux takes the *last* occurrence of a flag, so `['-c','/etc','sh']`
  overrides the canonicalized directory — confirmed, `#{pane_current_path}` returned `/private/etc`.
  And `guard()` inspects only `argv[0]`, which is `'tmux'`, so `['sh','-c','launchctl bootstrap …']`
  reaches the deny-listed binaries *through the choke point built to stop them*. The single-spawn-site
  claim is true; `env.ts:5-7`'s "enforceable promise" claim is not.

  no validation and without `path_policy`. `'../../../../tmp/pwn'` writes `/tmp/pwn.plist`, and

  file.

**The lesson is about the waiver, not the reviewer.** The CI reviewer's only blocking finding on #72
