## The same defect is in this repo's own tooling — #103

`scripts/sandbox.sh:23` computes `dirty` with `git status --porcelain`, which **excludes ignored files
by default**. Line 20 of that file says it *"Mirrors `inspect_sandbox()`"*. It mirrors the bug.

```
$ printf 'notes/\n' > .gitignore && mkdir notes && echo work > notes/plan.md
  dirty_files: 0
  safe_to_close: true
$ git status --porcelain --ignored
  !! notes/
```

This is the check CLAUDE.md §7.6 tells every agent to trust before teardown, and it is the check that
saved **1400 authored lines** on 2026-09-13 by reporting `dirty_files: 21`. That run's lesson was "a
sandbox with zero commits is not an empty sandbox." This is the same lesson one layer down: **a
sandbox reporting zero dirty files is not necessarily an empty sandbox either** — and the blind spot
is exactly where git is not already protecting the work.

Filed rather than fixed: `--ignored` alone would flag every `node_modules/`, and an inspect that always
says dirty is an inspect nobody reads. The distinction is **reproducibility, not tracked-ness**, and
it needs deciding before it is coded.
